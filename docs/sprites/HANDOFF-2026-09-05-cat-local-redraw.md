## 1. 结论先行

这次没有继续套用蛋精灵的脸，也没有依赖 AI 直接生成最终帧，而是用 PIL 在本地按像素绘制了一套三阶段猫的基础站姿：

- 小奶猫：`30×32`
- 猫仔：`36×38`
- 大猫：`44×48`

三张图都保留透明背景、橘色虎斑、米白脸颊/胸腹、粉色耳内和深棕描边。当前 v2 只是一套已经通过视觉确认的**基础稿**，还没有替换运行时正在使用的旧猫素材，也没有生成对应动画帧。

当前文件：

| 文件 | 用途 |
|---|---|
| `scripts/redraw-cat-local.py` | 可复现生成三张 v2 基础图的唯一绘图入口 |
| `scripts/test-cat-redraw.py` | 基础图契约测试：尺寸、透明边缘、脸、眼睛、嘴、头顶、手脚 |
| `assets/sprites/cat-baby-v2.png` | 小奶猫基础图 |
| `assets/sprites/cat-kid-v2.png` | 猫仔基础图 |
| `assets/sprites/cat-adult-v2.png` | 大猫基础图 |

这 5 个文件在本次交接时是未提交文件。运行时仍由 `src/app.js` 的 `PET_FRAMES` 指向原来的 `cat-baby`、`cat-kid`、`cat-adult` 及其旧状态帧。

## 2. 这次工作的复盘

### 2.1 之前为什么会看起来奇怪

1. **把蛋的表情逻辑套到猫身上**：蛋是简单几何脸，猫的三个成长阶段原本有更复杂的眼睛、鼻子、嘴和脸颊结构。共用一组脸部坐标会导致换阶段或换宠物后，五官落在错误位置。
2. **只按整体比例缩放脸**：从 48×48 设计稿缩到小奶猫/猫仔后，左右眼会因四舍五入变成不同宽度，嘴巴也会被压成黑块或残留一条黑线。
3. **给小奶猫补一条横向头顶描边**：这种“补线”在放大后看起来像机械封顶，破坏了耳朵到头顶的阶梯轮廓。现在小奶猫头顶只保留局部阶梯像素，大猫和猫仔继续使用自然轮廓。
4. **直接在已有脸上覆盖新嘴巴**：原嘴巴没有清理干净时，鼻子下方会多出黑线；大猫嘴巴过宽、过连续时会像人嘴。
5. **AI 图不适合直接当最终像素帧**：即使整体风格接近，眼睛、嘴巴、耳朵和尾巴的逐帧位置无法稳定复现，后续动画会继续漂移。

### 2.2 最终采用的办法

采用“**统一身体语言 + 阶段化尺寸 + 最终画布局部校准**”三层结构：

1. 在脚本里用一个 48×48 的内部设计网格画出同源猫体型：圆耳、短额头、橘色虎斑、米白脸颊和胸腹、卷尾、分开的前爪。
2. 根据成长阶段缩放身体并输出到固定尺寸画布；输出后底边对齐，保证运行时放入 48×48 canvas 时脚不会漂浮。
3. **缩放完成后再校准眼睛、鼻子、嘴巴、手脚边缘**。这些最终 patch 才是视觉锚点，不能再通过比例推算。

这套办法的关键不是让所有宠物共用同一组绝对坐标，而是让每个阶段拥有自己的局部坐标表；如果未来加入狗、狐狸或兔子，也必须为每个物种/阶段单独登记五官锚点。

## 3. 当前 v2 的视觉规则

### 3.1 形态规则

- 必须读作“猫”，不能有狐狸式的尖额头或过长的脸。
- 两只耳朵是圆润的猫耳，耳内为粉色；耳朵轮廓不应被脸部表情吞掉。
- 额头虎斑是短条带，止于眼睛上方；两眼之间不画细长向下的尖角纹。
- 脸颊是左右两块米白区域，中间留干净的鼻子/嘴巴通道。
- 尾巴是身体右侧的紧凑卷尾，不是狐狸式大扇尾。
- 前爪与身体有分离感；两侧各留一到两枚深色边缘像素即可，不能把整只手涂成黑块。
- 小奶猫的头顶描边使用短的阶梯状断线；不要为了“看起来完整”补一条长直线。

### 3.2 调色板（当前脚本为准）

以下是 `scripts/redraw-cat-local.py` 的实际 RGBA 值；旧规范中的近似色不能覆盖这里的实际值。

| 名称 | RGBA | Hex | 用途 |
|---|---|---|---|
| `INK` | `(57, 38, 43, 255)` | `#39262B` | 深棕轮廓、眼睛、嘴巴、爪边 |
| `SHADOW` | `(190, 87, 42, 255)` | `#BE572A` | 虎斑/身体暗部 |
| `FUR` | `(244, 157, 55, 255)` | `#F49D37` | 橘色主体 |
| `LIGHT` | `(255, 190, 70, 255)` | `#FFBE46` | 身体亮部 |
| `CREAM` | `(255, 242, 213, 255)` | `#FFF2D5` | 脸颊、胸腹、清理区域 |
| `PINK` | `(244, 132, 145, 255)` | `#F48491` | 耳内 |
| `NOSE` | `(207, 82, 105, 255)` | `#CF5269` | 鼻子 |
| `WHITE` | `(255, 253, 247, 255)` | `#FFFDF7` | 眼睛一像素高光 |

不要给 PNG 加背景色、阴影底板或抗锯齿。像素必须是硬边，缩放预览使用 nearest-neighbor。

## 4. 三阶段最终锚点

下表坐标都是**输出 PNG 的左上角为 `(0,0)`、x 向右、y 向下**。它们不是内部 48×48 设计网格坐标。

### 4.1 画布和五官

| 阶段 | 输出尺寸 | 左眼（含边界） | 右眼（含边界） | 左/右眼高光 | 鼻子 | 嘴巴像素 |
|---|---:|---|---|---|---|---|
| baby | 30×32 | x6–8, y11–13 | x15–17, y11–13 | (7,11), (16,11) | x11–12, y13–14 | (11,16), (12,17), (13,16) |
| kid | 36×38 | x7–10, y12–15 | x19–22, y12–15 | (8,12), (20,12) | x14–15, y16–17 | (14,19), (15,20), (16,19) |
| adult | 44×48 | x10–14, y15–19 | x25–29, y15–19 | (11,15), (26,15) | x19–20, y21–22 | (17,24), (18,25), (19,24), (20,25), (21,24) |

说明：

- 眼睛矩形内部除高光外都使用 `INK`，每只眼只保留一个 `WHITE` 高光点。
- 眼睛不能从 baby 的尺寸直接按比例推导；三阶段的最终矩形已经经过四舍五入和视觉校准。
- 鼻子要比旧稿更靠上；嘴巴直接位于鼻子下方，二者之间不能出现额外黑线。
- baby 的嘴巴必须保持三像素浅弧；kid 也是紧凑三像素猫嘴；adult 才使用五像素断笔形，稍大但不能画成连续人嘴。
- adult 嘴巴中心相对旧稿向右移动一格，与鼻子中心对齐。

### 4.2 手脚和头顶

| 阶段 | 前爪边缘像素 | baby 头顶阶梯描边 |
|---|---|---|
| baby | (7,25), (16,25), (7,26), (16,26) | (5,4), (6,4), (7,5), (8,5), (9,4), (13,4), (14,5), (15,5), (16,4), (17,4) |
| kid | (8,31), (20,31), (8,32), (20,32) | 不额外补线 |
| adult | (10,41), (24,41), (10,42), (24,42) | 不额外补线 |

这些点属于最终画布 patch。若身体尺寸或裁剪方式改变，必须重新生成预览并重新确认坐标，不能机械复制。

## 5. 后续动画的正确画法

### 阶段 A：先把 v2 基础稿接入运行时

1. 先在浏览器中确认 v2 三张基础图。
2. 决定是将 v2 重命名替换为 `cat-baby.png` / `cat-kid.png` / `cat-adult.png`，还是让 `PET_FRAMES.cat.stage` 暂时指向 v2 key。推荐先使用独立 v2 key，确认无误后再替换正式素材，避免回滚困难。
3. 更新 `src/app.js` 的 `PET_FRAMES` 后运行 `node scripts/build.js`。
4. 在首页和状态试验台确认三阶段尺寸、底边、尾巴和脸部没有跳动。

### 阶段 B：用 v2 生成基础表情

推荐顺序：

1. `idle-0/1`：只动身体高度、尾巴或耳朵，脸部保持锚点。
2. `blink`：只将两只眼同时替换为对称闭眼像素；鼻子、嘴巴、脸颊不动。
3. `eat-0/1/2`：按“低头咬 / 闭嘴嚼 / 抬头咽”改变头部整体姿态时，重新计算每个阶段的五官 patch；不要把 adult 的脸 patch 直接贴到 baby/kid。
4. `happy` / `excited`：先改身体跳跃和耳尾，再改眼嘴；表情幅度应逐阶段增大，但仍保持各自的眼睛宽度。
5. `sleep` / `sad` / `droopy` / `wash` / `grunt`：每帧都从对应阶段的 v2 基础图派生，保留脸颊和轮廓，只替换需要变化的眼、嘴、泪滴、泡泡或腮红。

### 阶段 C：走路动画

正面站姿和侧面走路是两套形体，不要把正面 v2 图横向压扁来冒充走路。

- 继续使用成年侧视 `cat-walk-0..6` 的动作逻辑作为参考。
- baby/kid 应有各自缩放或重画的侧视体型。
- 走路时优先移动腿、尾巴和身体重心；如果需要眨眼/张嘴，仍按该阶段自己的锚点处理。
- 尾巴摆动必须是尾部轮廓差分，不要整张图平移，否则会造成底边、脸和斑纹一起漂移。

## 6. 不能再踩的坑

- 不要让所有宠物、所有阶段共用一套绝对五官坐标。
- 不要把蛋的 `EGG_SPOTS`、蛋眼睛或蛋嘴逻辑直接套到猫脸上。
- 不要在缩放前把颜色映射到大量近似色；本地像素稿保持有限调色板和硬边。
- 不要先清空整块脸再重画状态表情；这样会抹掉猫原本的复杂脸部层次。
- 不要用一条长水平线补头顶描边。
- 不要用连续弧线画 adult 嘴巴；使用短的断笔像素形。
- 不要以“文件存在”代替视觉验收；必须打开 nearest-neighbor 放大预览，同时检查 1× 小尺寸观感。

## 7. 可复现命令和验收

从项目根目录执行：

```bash

# 验证本地重绘契约

# 验证既有精灵映射和资源契约
python3 scripts/test-sprite-contract.py

# 检查 JS 和空白错误
node --check src/app.js
git diff --check

# 接入运行时后重新打包
node scripts/build.js
```

当前已验证通过：

- `cat redraw contract: PASS`
- `sprite contract: PASS`
- `node --check src/app.js` 通过
- `git diff --check` 通过

视觉验收至少检查：

- baby 左右眼是否同宽、同高、同亮点；
- kid 鼻子下方是否无黑色残线；
- adult 嘴巴是否与鼻子居中且不像人嘴；
- baby 头顶是否是自然阶梯轮廓而不是硬直线；
- 三阶段前爪、尾巴和底边是否在 48×48 运行时画布中稳定。

## 8. 下一次工作的建议起点

下一位模型不要从重新设计三只猫开始。建议直接：

1. 读取本文件第 3、4 节；
2. 打开 `assets/sprites/cat-*-v2.png` 和 `scripts/redraw-cat-local.py`；
3. 先生成一张三阶段 v2 放大对照图；
4. 以对应阶段 v2 为底制作 `idle` 和 `blink`，每次只改变一个动画因素；
5. 每增加一组帧，就在 `scripts/test-cat-redraw.py` 或新的状态测试中加入坐标契约；
6. 通过测试后再改 `PET_FRAMES`、build 和浏览器预览。

最重要的判断标准是：**猫的成长阶段可以共享风格和身体语言，但不能共享未经校准的脸部几何。**
