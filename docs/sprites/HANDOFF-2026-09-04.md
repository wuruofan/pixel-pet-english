## 5. 工作流程

### 5.1 生成新精灵帧

推荐方案（蛋 v2 验证有效）：**AI 生成底图 + 程序精修关键特征**，而非纯 AI 或纯程序。

1. **AI 生成底图**：用 `image_edit` 以现有 `cat-adult.png` 为风格参考，生成目标帧的底图（纯白背景，chunky pixel，橘猫同源调色板）。
2. **程序处理**：写 Python 脚本（参考 `scripts/process-egg.py`）：
   - flood-fill 去白背景 → 裁剪 bbox → BOX 缩放到目标尺寸
   - **先缩放再映射调色板**（先映射再缩放会产生几百种抗锯齿中间色）
   - 程序精修关键特征（描边、眼睛、嘴、腮红等）
3. **派生差分帧**：基于主帧用程序修改（眼睛/嘴/位移），确保真差分（像素数不同）。
4. **放到 `assets/sprites/`**，命名与 `PET_FRAMES` 映射一致。

### 5.2 构建

```bash
node scripts/build.js
# 输出 pixel-pet-english.html，自动扫描 assets/sprites/*.png 注入 base64
```

构建后验证：
```bash
grep -c 'cat-xxx' pixel-pet-english.html   # 确认新帧 key 已注入
```

### 5.3 预览

```bash
# 方式一：no-cache 预览服务（推荐，避免缓存）
node scripts/serve-no-cache.js

# 方式二：普通 http server
python3 -m http.server 57321 --bind 127.0.0.1
```

打开 `http://127.0.0.1:57321/pixel-pet-english.html`。
- 普通 http server 可能有缓存，用 **Cmd+Shift+R 强刷**。
- 试验台（test-bench）页面可以点 chip 预览各表情动画。

### 5.4 验证清单（每次新动画完成后）

- [ ] 文件已落到 `assets/sprites/` 并符合命名约定
- [ ] `src/app.js` 的 `PET_FRAMES[cat].expr` / `.stage` 已登记新键（如需要）
- [ ] `drawPet` PNG 分支能命中该键（`PET_IMG_EL[key]` 存在）
- [ ] `node scripts/build.js` 重新生成 HTML，grep 确认新 key 注入
- [ ] 模拟 `drawPet` 渲染（48×48 居中+底对齐）确认画面正确
- [ ] 浏览器预览确认动画效果
- [ ] 真差分验证：各帧不透明像素数不同（排除同图复制）

### 5.5 提交

```bash
git add <相关文件>
git commit -m "feat(sprites): ..."
```

## 6. 技术规范

### 6.1 画布与渲染

- **运行时画布**：48×48 px，透明背景
- **drawPet 逻辑**：`ctx.drawImage(el, Math.round((48 - el.width) / 2), 48 - el.height)` — 居中+底对齐
- **蛋帧内容尺寸**：29×36（小于 48×48，drawPet 自动居中）
- **猫帧内容尺寸**：尽量接近 48×48（站姿底边对齐）
- **网格基准**：16×16 逻辑格（3× 像素放大）

### 6.2 调色板（橘猫同源）

| 角色 | 色值 | 用途 |
|---|---|---|
| INK | `#2a0902` | 深棕描边/眼睛 |
| CREAM | `#fdf7ec` | 米白（蛋身/猫腹） |
| PINK | `#fa8778` | 腮红/舌 |
| WHITE | `#ffffff` | 眼高光 |
| 橘色系列 | `#ef8a76` / `#b85a3a` / `#f6c445` / `#fcab34` 等 | 猫身体/斑点 |

> 规范文档里写的是 `B=#ef8a76 / S=#b85a3a / A=#f6c445 / W=#fff6ea / O=#3a2a1f`，蛋 v2 实际用的是 `#2a0902` 描边（更深）。**以实际代码和 PNG 为准**，统一时注意。

### 6.3 命名约定

```
{species}-{animation}[-{index}].png

species:   cat（小猫）
animation: baby | kid | adult | walk-{0..6} | eat | sleep | happy | excited
                | idle-{0,1} | blink | droopy | sad-{0,1} | egg | egg-idle-{0,1}
                | egg-blink | egg-eat | egg-happy
```

> 实际命名以 `src/app.js` 的 `PET_FRAMES` 映射为准。生成新帧前先 grep 确认代码里期望的 key。

### 6.4 动画间隔（PET_EXPR_INTERVAL）

- idle：800ms
- blink：170ms
- eat：280ms
- happy：180ms
- walk：110ms/帧

### 6.5 多帧动画机制

`drawPet` 按 `PET_FRAMES[species].expr[expression]` 取帧数组，`startExprAnim` 轮询翻帧（`petAnim.exprIdx[expr]`）。单帧数组静态显示，多帧数组按间隔切换。

## 7. 已知坑和经验

### 7.1 AI 生图翻车记录（避免重复）

- **纯文字 prompt → 拟人化太光滑、像素不够 chunky**：必须以现有 `cat-adult.png` 为风格参考（image_edit 图生图）。
- **图生图 → 透明背景渲染成黑色**：AI 生成时用纯白背景，程序 flood-fill 去白，不要让 AI 直接生成透明底。
- **图生图 → 裁切过头只画脸**：prompt 里明确"完整蛋身/猫身，48×48 画布内完整"。
- **闭眼指令被忽略**：AI 底图只生成主帧（睁眼），闭眼/眯眼/张嘴等差分用程序派生，不要靠 AI 逐帧生成。
- **结论**：AI 只负责主帧底图，差分帧全部程序派生。这是蛋 v2 成功的关键。

### 7.2 调色板映射顺序

- **必须先缩放再映射调色板**。先映射再缩放会产生几百种抗锯齿中间色（实测 337 种），缩放后映射只有目标调色板的颜色。

### 7.3 假差分识别

- 逐帧计算不透明像素数：如果多帧像素数完全相同，大概率是同图复制（假差分）。
- 真差分的各帧像素数应该不同（眼睛/嘴/位移变化）。
- 位移版本（整体右移 1px）像素数相同但 bbox 不同，可作为 idle wobble，但不能作为 eat/sleep 等状态差分。

### 7.4 斑点定制架构

- 蛋的斑点不在 PNG 里，由 `drawPet` 运行时叠加（`EGG_SPOTS` 坐标表 + 宠物主色）。
- 猫的身体色/斑纹目前画在 PNG 里。如果未来要做猫的毛色定制，可参考蛋的方案：通用底 + 运行时叠加斑纹。
- `PET_PALETTES[sp.pals[1]].B` 是取宠物身体主色的标准方式（字符画分支和蛋斑点都用这个）。

### 7.5 构建与缓存

- `node scripts/build.js` 自动扫描 `assets/sprites/*.png`，新增/删除 PNG 后必须重新 build。
- 普通 `python -m http.server` 有缓存，改了 HTML 后用 Cmd+Shift+R 强刷，或用 `node scripts/serve-no-cache.js`。
